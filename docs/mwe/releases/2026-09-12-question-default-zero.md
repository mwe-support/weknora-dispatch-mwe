# 2026-09-12 问题生成默认 0 与现有知识库迁移

## 范围与版本

- 上游：WeKnora v0.7.2；主项目：`mwe-support/weknora-dispatch-mwe`；目标分支：`weknora-v0.7.2`。

- 涉及前端数量输入、后端有效数量判定、显式迁移命令、在途作业兼容衔接及测试；没有 MCP 专属修改。

## 用户行为

- 新建知识库、知识库高级设置、上传确认三个入口统一提供 0–10 的整数输入。0 不生成问题；1–10 按用户选定的数量生成。
- 删除数量为 0 时自动回退到 3 的处理，包含上传、URL、手动文档、复制/移动、重新解析、后处理派发和生命周期计划。
- 保留原有 `enabled` 字段兼容 API，但 `enabled=true, question_count=0` 也视为关闭。接口拒绝 -1、11 等越界值。
- 关闭状态隐藏自定义问题要求编辑区，已有要求保留；恢复正数后可继续使用。
- 零数量不创建问题及问题索引阶段，正文分块、正文/图片索引、发布、摘要等独立阶段保留。手动重新生成遇到关闭配置时返回明确错误，不以空结果清空已存在的问题。

## 现有知识库与在途作业

直接修改知识库设置会改变 `ConfigurationRevision`，导致旧作业与当前配置不匹配。本批增加明确、受限且有审计记录的问题停用操作：

1. 在同一事务中读取修改前后的完整处理输入，只有“问题配置”变化且新配置关闭时才允许衔接；其它配置变化继续使用原有版本校验，不获得例外。
2. 核对作业原配置摘要；保留作业 ID、代次、源修订、原始计划摘要、已确认产物和发布指针。事件记录修改前后的配置摘要。
3. 仅停用 `questions`、`question`、`question_index` 及其子步骤。未完成单元标为 `skipped`，撤销 lease 和后续运行时间；已成功单元及其产物保留。
4. 取消问题步骤的完成要求，并从旧版本清理步骤中移除对应依赖。非问题消费者异常引用会拒绝迁移，不直接放宽其它依赖。
5. 问题错误以 `feature_disabled` 结束处理，原失败事件保留；不把用户停用冒称为执行成功，其它失败仍保留。
6. 保留原始 `PlanDigest` 和步骤输入指纹；为后续重复源扫描记录严格的无问题计划兼容摘要。只有该摘要及当前配置版本均匹配才接受重复准入，任意更改源输入的计划仍被拒绝。

批量命令为 `/app/question-default-zero`：默认执行完整事务后回滚，`--apply` 才提交。现有 `system_settings` 中的内部回执 `mwe.migration.question_defaults_zero.v1` 保证只应用一次，不显示为可编辑系统设置。重启应用或重复运行命令不会覆盖用户后来选择的正数。

批量迁移只写知识库的问题配置及更新时间，不使用整行保存，避免将无关字段的 `NULL` 顺带规范化。知识库编辑 API 仍保留原有完整保存行为；只有受限的问题停用变更可对在途作业进行上述衔接。
